源文 :: 俄语主版本

本规格提出 SUTI 共同活态系统的本地内容引擎与机器人适配器。关怀天使、都市萨满或达摩武士形象由使用者自愿开启；每条意象路径都有同等可用的普通语言表述。机器人帮助寻找、表达和检验下一步；有关援助、资助、投诉、人员角色与支出的最终决定，由获授权的人作出。

预期的第一个结果

选择语言 → 阅读所提供的内容及当前限制 → 选择问题或现成主题 → 获得包含来源与可选行动的短卡片 → 自行保存或结束路径。阅读公开材料无需个人档案或注册。每个界面都可暂停、跳过、返回和退出。默认不索取姓名、出生日期、健康、证件、财务、家庭情况或私人经历。

最小版本包括本地知识目录、13 条语言路径、已发布卡片搜索、自愿参加的 NITYA 任务，以及个人书签导出。即时通讯集成、用户消息存储、AI 服务、社群、财务模块和资助申请接收，并不自动属于这个最小范围。

拟议架构的组成

下图保留俄语源文作为引文；其组成与边界在后文逐项说明。代码、路径和稳定标识符不翻译。

публичный каталог в .vault
    ↓ проверка источника, прав, приватности и языка
детерминированный сборщик публичного пакета
    ↓ allowlist + manifest + SHA-256
локальный read-only контентный движок
    ├─ Obsidian / Markdown
    ├─ доступный локальный HTML
    └─ опциональный адаптер бота
          ↓ только отдельный разрешённый runtime
       сессия пользователя / принятые им действия
          ↓ отдельное согласие и минимизация
       личное пространство пользователя вне публичного каталога
  1. 内容目录。 包含稳定的 entity_id、来源、意义不变量、范围、边界、权利、成熟度及关系。公开包不得列出私人路径、联系方式或个人原始经历。
  2. 语言层。 每个对象有一个已确定的主版本，各语言直接据此编写。不自动把未经核验的译文当作完成文本替入。
  3. 路由器。 采用确定性命令、模块与卡片。首版无需生成模型。回答包含清楚、可行的步骤与明确状态。
  4. 会话。 当前界面的短期状态，默认保存在进程内存或使用者设备，而非共同公开数据库。
  5. 适配器。 Telegram 等渠道单独连接；密钥放在 .vault 外，校验更新来源，关闭非必要事件。技术 transport ID 视为个人标识符，不进入公开包或常规日志。
  6. 个人存储。 使用者选择保存时，数据进入有明确所有者、访问限制、期限和经测试删除机制的独立私有空间。物理隔离不同于在公开 vault 内建一个文件夹。
  7. 编辑队列。 贡献、异议、更正与投诉具有限定访问、指定负责人和状态。公开日志只展示获准的汇总决定。
  8. 发布检查。 纳入文件前检查 allowlist、权利、隐私、来源、支持格式、链接、语言和 SHA。错误使该次发布构建停止。

这是接口设计，不是代码已存在的证明。实施方案须在核对现有项目、团队支持、部署与本地存储要求后选择。

13 种语言与内容加载

语言标识 :: ru, en, es, pt-br, zh-hans, hi, fr, ar, bn, eo, sa, la, yzh

拟议公开包结构如下，保留源文代码及注释：

content.json 明确列出文件、大小、SHA-256、规范版本和允许的语言。语言状态与文件是否存在分开记录：not-started、draft、meaning-reviewed、native-or-expert-reviewed、release-approved。这些是新契约拟议的 enum，不经单独迁移便不改写历史登记。

选择语言时，引擎检查卡片是否存在，以及其状态是否适用于所选模式。若没有文本，用界面语言如实说明，并让人主动选择现有语言。禁止不作说明就用俄语或英语替代空缺语言。主版本更新后，依赖的语言版本标为需要重新比对；旧 SHA 不证明新内容的意义已核验。

阿拉伯语界面使用 dir="rtl"，单独检查阅读、表格、数字与混合标识符。梵语、拉丁语需要专家；YZH 需要作者批准的释义、展开说明和理解检验。在这些依据具备前，语言版本如实保留 HOLD。文字意义无需动画、颜色或特殊符号也能理解。

个人自由文本不是必填项。默认日志不保存消息正文、完整 IP、地理位置、联系方式或援助经历。不可为了“完整地图”从通讯录、聊天或档案加入他人数据。跨渠道关联须有所有者另行清楚选择和理由，否则不进行。

导出通过当前已认证会话核验所有者，仅包含其本人数据；执行前展示格式和范围。删除先说明受影响记录及可能的合法例外，再要求所有者确认，结果区分 deleted、retained_with_basis、unknown。服务不能控制其他通讯工具基础设施或他人备份时，不得承诺从其中删除消息。服务端备份须有经测试的退出保存期限及恢复处理方案。

AI 与人的决定

生成是可选项，首版可完全确定性运行。以后接入模型时，应让使用者知道哪些数据将被送往何处、为何使用及保存多久；AI 处理另行选择。默认不向外部供应商发送个人资料库或申请。本地模型的技术可用性不替代处理依据。公开卡片与用户自由文本隔离；文档中的指令视为数据，而非权限。

模型回答引用获准来源，区分观察、解释、假设与未知。依据不足时，说明限制并提供可行、可检验的步骤。模型不指定身份、不诊断、不评判人的价值、不承诺援助，也不决定支付。神经议事会明确标为编辑模拟；人的实际回应单独记录。

视觉与内容的共同开发

整体美学是宁静的土地之光、易读排版和适中密度；不用装饰符号承载必要意义。关怀、火烈鸟、隼、Garuna、Finist、都市萨满及 Samurai Dharma 的意象，作为自愿艺术层开启，并标明来源与作者。基本场景无需动画、声音或符号。应提供手动控制、减少动态、键盘操作、可见焦点、足够对比与文字替代；实现是否满足这些要求须另行验证。

合作按清楚的结果推进：商定任务及权利 → 选择一条使用路径 → 比较若干草图 → 检验理解与可访问性 → 交付可编辑源文件 → 制作原型 → 验证 → 接受限定成果。伙伴自行提出合适的协作框架、形式、范围、时限与期望报酬。免费赠与作者材料与开发委托分开约定；赠与不产生免费劳动义务。在明确接受前，不宣布伙伴关系、同意、共同品牌或他人材料许可。

可合作的事项包括语言机器人、13 语目录、图谱可视编辑器、可访问的 NITYA 任务、学习卡片、生成世界、自愿短故事系列，以及透明的小型项目系统。报酬范围、币种、代码与设计权利、支持、基础设施及验收标准，在另行达成一致的订单中确定。伙伴公开页面及参加其课程，不赋予提取封闭课程、受众数据或把他们称为参与者的权利。

实施阶段与验收

阶段具体成果进入下一阶段的依据
A · 目录规范、13 模块、allowlist、manifest、来源与真实语言状态所选集合适合公开；链接及 SHA 已检验
B · 离线原型阅读、选语言、搜索、任务及个人书签导出主要路径可人工、用键盘及离线完成
C · 演练合成会话、拒绝、撤回、删除、审核、故障与恢复预期结果已核验；所有者之间无泄漏
D · 适配器在限定环境另行授权的机器人运营者、密钥、数据、日志、限制与保护已确认
E · 限定试点一个选定环境与已同意的成年参与者已接受角色、容量、语言、关怀及停止标准
F · 扩展评估效用并依据数据调整人另行决定；每个新环境分别核验

实现的可检验验收标准：

  1. manifest 恰好包含指定的 13 个模块 ID 与 13 个语言标识，不把空语言分支当作完整翻译。
  2. 每张展示卡片都有目的、来源、版本、使用权、成熟度及可用返回路径。
  3. 缺失语言如实显示状态；语言切换明确，没有隐藏替换。
  4. 阿拉伯语以 RTL 阅读，混合 ID 不破坏意义；梵语、拉丁语和 YZH 有所需的独立依据。
  5. 阅读公开材料无需问卷，不索取最小个人档案数据。
  6. /pause、/exit 与退订在所有已测状态有效；暂停不启动新行动。
  7. 导出只含当前所有者数据；其他所有者的尝试被拒绝。
  8. 删除确认范围，确实移除可控制记录，并如实显示合法保留及不可控制部分。
  9. 常规日志不含消息正文、密钥、申请、私人路径或个人经历。
  10. 读取 allowlist 外路径的尝试、内容内嵌指令及不适合文件，都不作为命令执行。
  11. 自愿贡献经人工审核、利益冲突或回避处理，提供理由和申诉路径；保留原作者署名。
  12. 游戏层可关闭；普通文字传达相同意义；不惩罚跳过，也不设人的尊严等级。
  13. 未满足各自经确认的条件前，青少年接入、支付、筹款及资助申请关闭。
  14. 没有另行批准的 runtime 与清楚的数据选择，不启动网络或外部模型操作。
  15. 在实际界面核验键盘、焦点、阅读、对比、文字替代及减少动态的可访问性。
  16. backup/restore 有经验证的结果；恢复不会违反已接受政策而带回已删记录。
  17. 负载和故障不使会话混杂；使用者获得清楚状态和可用出口。
  18. 报告注明确切版本、环境、场景、预期及观察结果；PASS 只限已检验范围。

上述标准当前全部为 NOT_RUN：文件提出要求，不证明已实现。下一技术步骤是在 A 的集合核验后，选择一组公开卡片并实施 B 离线原型。
