# suti vault care

Use when maintaining or preparing a SUTI vault for another person or compatible agent.

1. Confirm the exact vault root and its local instructions.
2. Read the entry route and follow its links to the intended outcome; flag dead ends, ambiguous destinations, and unnecessary loops.
3. Check Markdown links, attachment targets, configuration syntax, enabled Obsidian snippets, and the presence of referenced files.
4. Separate static configuration evidence from settings actually observed in the Obsidian interface. Never report activation or visual success from a file check alone.
5. Review proposed changes for personal data, credentials, third-party rights, hidden network activity, and accidental access expansion.
6. Prefer a small reversible correction. Keep originals, unknown provenance, and uncertain dependencies on hold.
7. Recheck the changed route and report exact evidence, remaining holds, and a clear return path.

Do not install or enable community plugins, publish, copy private data, or make destructive changes without a separate explicit instruction.
