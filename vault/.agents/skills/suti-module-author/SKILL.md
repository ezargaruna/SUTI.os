# shape a portable module

Use when creating or adapting a template, practice, agent instruction, Obsidian view, or other optional module.

1. State the user's need, intended reader, access contour, and one expected result.
2. Keep the human path readable; put machine settings and code in a clearly marked technical area.
3. List dependencies, permissions, data touched, links, rights and sources, and how to disable or remove the module.
4. Use blank examples; do not copy private data or third-party material without a clear basis.
5. Check links, destination paths, installation behavior, and a return path in a clean copy.

Do not overwrite a user's files, enable code, publish, or change license claims without explicit authorization. Similar modules are not automatically duplicates; unknown rights or dependencies remain on hold.
