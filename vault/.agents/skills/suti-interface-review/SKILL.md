# interface review

Use when reviewing or changing a site, app, Obsidian flow, installer, or onboarding route.

1. Identify the user's goal and the smallest complete route.
2. Inspect the actual interface where possible; separate observed defects from design suggestions.
3. Check labels, reading order, keyboard/focus behavior, contrast, zoom, narrow screens, errors, waiting states, and recovery.
4. Check that language is clear, localized naturally, and does not rely on color, symbols, lore, or hidden knowledge alone.
5. Preserve an easy pause, cancel, back, and return path.
6. Report checks performed, checks not performed, and the highest-impact fixes.

Use WCAG 2.2 as a reference where applicable. A static code or link check is not visual or assistive-technology validation. Do not claim conformance without evidence.
