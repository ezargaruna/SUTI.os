# make a crystal

Use when the user asks to organize notes, write a reusable practice, or prepare a transferable file.

1. Confirm the intended reader, use, and access boundary.
2. Preserve distinct ideas and disagreements; do not compress away a meaningful difference.
3. Write one purpose per file in plain language.
4. Include only what helps: when it helps, the distinction, a small procedure, an example, a boundary, and a useful route onward.
5. Use ordinary Markdown and relative links. Add metadata only for a real machine need.
6. Keep private details out of shared or public output; when uncertain, omit and flag for review.
7. Check links and the reader's return path.

Do not copy a source's distinctive expression or structure without permission. Do not claim validation that was not performed.
