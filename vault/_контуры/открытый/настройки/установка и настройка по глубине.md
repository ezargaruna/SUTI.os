# установить и настроить по глубине

> **∴ суть** · помогает открыть, настроить, упростить или перенести SUTI.os без лишних программ и скрытой передачи данных.

**Начать можно без Python, Git, плагинов, аккаунта и терминала.** Хранилище остаётся обычными файлами Markdown; приложения и дополнительные инструменты нужны только для выбранных задач.

> **это справочник по техническим действиям, не тарифная лестница.** Открытая SUTI.os остаётся полной и пригодной для самостоятельной работы. Plus и Pro — отдельные, необязательные комплекты углублённой настройки; краткое описание есть в [[сад/доступ и расширение.md|обзоре дополнений]].

## сначала выбери глубину

| глубина | что сделать | что потребуется |
|---|---|---|
| **1 · открыть** | скачать проверенную сборку, распаковать, открыть как папку или vault, выбрать одну входную страницу | файловый менеджер; Obsidian необязателен |
| **2 · настроить** | выбрать личные контуры, шаблоны, Canvas и Bases, убрать ненужные ссылки из личной навигации | Obsidian или любой редактор Markdown |
| **3 · развивать** | создать персональную копию установщиком, перенести выбранные файлы, писать свои модули и автоматизацию | Python нужен только для встроенных скриптов; Git нужен только для клонирования и управления изменениями |

не нужно проходить уровни подряд. остановись на том, который решает задачу.

## глубина 1 · открыть без программирования

1. получи сборку только из официального канала, который можешь проверить. не запускай команды из неизвестного сообщения и не скачивай архив по неподтверждённой ссылке.
2. распакуй папку средствами macOS Finder, Windows Explorer, Linux file manager или приложения Files на мобильном устройстве.
3. открой `начать.md` в браузере, текстовом редакторе или Obsidian. В Obsidian выбери **Open folder as vault / Открыть папку как хранилище**.
4. открой [[карта SUTI.md|карту SUTI]] и выбери один маршрут. личные записи создавай внутри своей копии.
5. сделай резервную копию, прежде чем менять крупные разделы или переносить старые данные.

**Obsidian не обязателен для чтения.** Если решишь установить его, бери приложение с официальной страницы [установки Obsidian](https://obsidian.md/help/install): там есть отдельные способы для Windows, macOS, Linux, Android и iOS. чтобы открыть папку, Obsidian предлагает существующий каталог как vault — см. [официальный порядок открытия vault](https://obsidian.md/help/vault).

**Android** · распакуй проверенную папку в доступное хранилище устройства, затем выбери её как существующий vault в Obsidian. **iPhone/iPad** · используй файловое расположение, поддерживаемое приложением и твоим способом синхронизации; папку можно разместить в iCloud Drive/Obsidian, если этот контур выбран. на мобильном сначала проверь, что заметки доступны офлайн и попадают в резервную копию. см. [официальные правила синхронизации Obsidian для разных устройств](https://obsidian.md/help/Getting%2Bstarted/Sync%2Byour%2Bnotes%2Bacross%2Bdevices).

В этой копии Canvas и Bases используют встроенные средства Obsidian; дополнительные community plugins не требуются. установить плагин можно позже, после проверки автора, открытого кода, заявленных возможностей, обновлений, совместимости и способа отключения. **Ограничения доступа плагинов нельзя надёжно сузить средствами Obsidian**: плагин может читать файлы vault или выходить в сеть в пределах доступа приложения. поэтому проверяй его в отдельной копии, особенно если работаешь с чувствительными сведениями. см. [официальное описание безопасности плагинов](https://obsidian.md/help/plugin-security).

## получить проверенную копию

если владелец опубликовал адрес официального выпуска, можно загрузить готовый архив браузером. **Публичный адрес GitHub или сайта нельзя угадывать**: сначала проверь имя владельца, репозиторий, лицензию, состав архива и контрольные суммы.

если Git уже установлен и адрес репозитория подтверждён, команда клонирования выглядит так.

**macOS или Linux · терминал**

```sh
git clone --depth 1 "<официальный URL репозитория>" "$HOME/Documents/SUTI.os"
```

**Windows · PowerShell**

```powershell
git clone --depth 1 "<официальный URL репозитория>" "$HOME\Documents\SUTI.os"
```

замени текст в угловых скобках на адрес, опубликованный владельцем. если Git не установлен, не устанавливай его ради единственного скачивания: используй проверенный архив через браузер. если Git нужен для регулярной работы, устанавливай его по [официальному руководству Git](https://git-scm.com/book/en/v2/Getting-Started-Installing-Git).

## глубина 2 · настроить под свою жизнь

открой [[_контуры/открытый/настройки/сделать хранилище своим.md|порядок персональной настройки]] и начни с вопросов:

- какие области жизни мне нужны сейчас: личное, близкие, работа, дело, учёба, творчество или другие?
- какие записи должны оставаться только у меня?
- где я хочу быстро сохранять входящие заметки?
- какие формы я действительно использую?
- какие разделы можно скрыть из моей карты, не удаляя исходные материалы?

### настроить Obsidian

1. открой эту папку как отдельный vault.
2. проверь, что включён сниппет `suti-canonical` и работает выделение активного файла. если его не видно, обнови окно и включи сниппет в **Settings → Appearance → CSS snippets**.
3. оставь встроенные функции, которые помогают твоей работе: поиск, быстрый переход, Canvas, Bases, шаблоны или заметки по датам. всё остальное можно не включать.
4. создай собственную стартовую страницу и добавь в неё несколько используемых маршрутов.
5. проверь настройки резервного копирования и синхронизации отдельно: облачная синхронизация — передача данных провайдеру, не просто локальная настройка.

клавиши и три уровня настройки собраны в [[_контуры/открытый/настройки/Obsidian — три глубины.md|коротком путеводителе Obsidian]]. не нужно менять системную тему, устанавливать значки и оформлять каждый файл до начала работы.

### убрать то, чем не пользуешься

безопаснее сначала **спрятать**, а не удалять:

1. сделай копию папки или используй историю версий;
2. выбери модуль, который хочешь убрать;
3. найди ссылки на его страницы во всей сборке и проверь, не использует ли его другой модуль;
4. убери только ненужную ссылку из своей навигации либо перемести весь модуль в личную папку «архив»;
5. открой оставшиеся маршруты и проверь, что они понятны без удалённого раздела;
6. очищай архив только после периода использования и отдельной проверки.

папка `архив` — удобное место хранения, но не защита доступа. для настоящей приватности используй отдельную папку пользователя, отдельный vault, права устройства или шифрование. не удаляй `_system`, `_технэ`, манифест или настройки установщика, пока не понимаешь их зависимость.

## перенос старой базы знаний

### вручную · самый понятный путь

1. создай новую пустую копию SUTI.os; старый источник оставь нетронутым;
2. выбери несколько материалов с ясной целью, а не весь архив;
3. проверь авторство, право на перенос, приватность и необходимость каждого файла;
4. скопируй выбранные заметки в подходящие личные контуры, не перенося секреты, чужие переписки и чувствительные данные;
5. переименовывай и перемещай файлы внутри Obsidian, чтобы приложение могло обновить ссылки;
6. проверь ссылки, структуру и резервную копию новой папки;
7. сохраняй старое хранилище до тех пор, пока не убедишься, что нужные материалы доступны.

### глубина 3 · локальный просмотр списка через Python

используй это только если готов работать в терминале. установщик и переносчик используют стандартную библиотеку Python; дополнительные пакеты `pip` не нужны. для текущего установщика требуется **Python 3.10 или новее**.

сначала проверь, доступен ли он уже.

**macOS или Linux**

```sh
python3 --version
```

**Windows · PowerShell**

```powershell
python --version
```

если команды нет, вернись к ручному пути. если действительно нужен установщик, устанавливай Python только с [официальной страницы Python](https://www.python.org/downloads/) или по инструкции своей системы. для Windows официальный Python Install Manager поддерживает команду `python`; старый launcher `py.exe` в новых выпусках объявлен устаревающим, поэтому `py` оставлен только как запасной вариант для уже имеющейся установки. см. [официальную документацию Python для Windows](https://docs.python.org/3/using/windows.html).

когда проверенная копия SUTI открыта в терминале:

**macOS или Linux · создать личную копию**

```sh
python3 _system/tools/suti_setup.py
```

**Windows · PowerShell, создать личную копию**

```powershell
python _system\tools\suti_setup.py
```

если на старой Windows-компоновке работает только launcher:

```powershell
py -3 _system\tools\suti_setup.py
```

установщик задаёт до четырёх коротких настроек и одно подтверждение. он создаёт новую папку, проверяет список разрешённых файлов и не переносит личные данные автоматически.

### переносчик · сначала список, затем ручной отбор

скрипт сначала создаёт локальный перечень путей, размеров и контрольных сумм. **Он не читает содержимое файлов**, но сами названия файлов могут быть личными — не пересылай этот перечень агенту или другому человеку без проверки.

**macOS или Linux**

```sh
python3 _system/tools/suti_transfer.py inventory "/путь/к/старому-хранилищу" --output "$HOME/Documents/suti-transfer-selection.json"
```

**Windows · PowerShell**

```powershell
python _system\tools\suti_transfer.py inventory "D:\Путь\к\старому-хранилищу" --output "$HOME\Documents\suti-transfer-selection.json"
```

открой JSON локально. Для каждого выбранного файла сначала проверь его назначение, содержание, право переноса и приватность. Отметь `select: true`, `review: "проверено человеком"` и одну из категорий `личное`, `открытое` или `командное`. Только после этого запусти копирование в **отдельную пустую папку**.

**macOS или Linux**

```sh
python3 _system/tools/suti_transfer.py copy "$HOME/Documents/suti-transfer-selection.json" --destination "$HOME/Documents/SUTI.моё"
```

**Windows · PowerShell**

```powershell
python _system\tools\suti_transfer.py copy "$HOME\Documents\suti-transfer-selection.json" --destination "$HOME\Documents\SUTI.моё"
```

переносчик не перезаписывает существующие файлы; исходные данные остаются на месте. сам перенос не доказывает, что новая структура или все ссылки подходят человеку — проверь результат в приложении.

## создавать и обменивать модули

новый модуль должен решать одну понятную задачу и иметь:

- краткое назначение и начальную страницу;
- простую инструкцию включения, отключения и удаления;
- зависимости и ссылки на нужные материалы;
- пустые формы вместо чьих-то заполненных личных данных;
- автора, права и лицензию для обмена;
- проверку ссылок, приватности, совместимости и резервного возврата.

проверяй новый модуль в отдельной копии. не запускай код из модулей автоматически. чужой шаблон нельзя распространять только потому, что он работает в Obsidian.

## что можно пропустить

для обычного использования не нужны Python, Git, терминал, community plugins, AI, синхронизация, календарная интеграция или импорт всей старой базы. добавляй инструмент, только если можешь назвать задачу, которую он решает, данные, к которым получает доступ, и способ его отключить.

## если что-то пошло не так

- не видишь выбранный файл слева — обнови Obsidian и проверь CSS-сниппет;
- потерялись ссылки — не переименовывай массово; верни резервную копию и проверь на маленькой папке;
- установщик остановился из-за контрольной суммы — не обходи проверку, получи согласованную сборку;
- переносчик не копирует файл — проверь его выбор, категорию приватности и отсутствие файла с тем же именем;
- команда неизвестна — не устанавливай случайные зависимости, используй ручной путь или запроси помощь.
