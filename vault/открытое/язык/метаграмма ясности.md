# метаграмма ясности

это дополнительный способ кратко отмечать смысловые части записи. он не является шифром, языком управления реальностью или исполняемым кодом. каждая запись должна оставаться понятной после раскрытия символов.

## простая форма

```text
ситуация :: что произошло
факт :: что можно проверить
версия :: как я это объясняю
важно :: что имеет значение
шаг → что попробую
возврат ↺ когда пересмотрю
```

## пример

```text
ситуация :: коллега не ответил два дня
факт :: ответа пока нет
версия :: возможно, он избегает разговора
неизвестно :: почему ответа нет
важно :: согласовать срок проекта
шаг → задать нейтральный вопрос о сроке
возврат ↺ после ответа или завтра
```

## правила

- сначала используй обычные слова
- один знак — одно устойчивое значение в рамках конкретной заметки
- обозначай предположение как предположение
- не сжимай медицинские, юридические, финансовые или опасные инструкции так, чтобы потерялись условия
- не кодируй скрытый слой, который другие не могут проверить
- если запись трудно прочесть вслух, добавь обычную версию
- тишина может означать паузу; она не означает согласие

## палитра форм

эти формы можно смешивать только тогда, когда каждая помогает передать мысль. для обычной работы достаточно ясной фразы.

| форма | простое значение | что оставить рядом |
|---|---|---|
| кённинг | составное поэтическое название | обычное значение и границу образа |
| агма | авторская короткая языковая форма для совместного внимания | расшифровку и ситуацию применения |
| метаграмма | компактная запись частей смысла и связей | читаемое раскрытие знаков |
| протограмма | личный знак для повторяющегося действия или наблюдения | действие, область применения и способ отмены |
| скриптоцереяна | рабочее авторское имя для интеграционной записи, соединяющей ветви SUTI | связь между ветвями, обычное прочтение и ссылки |
| песенный манифест | короткий ритмический текст о выбранном принципе или связи | прямую формулировку принципа и добровольность использования |

для новой формы добавляй небольшой манифест только если он нужен для повторного использования или передачи другому. поля и примеры находятся в [[../../_system/expression-manifest.schema.json|машинной схеме выразительной формы]]. она помогает описать форму, но не исполняет её.

### теги и метатеги

`теги` помогают найти тему: например, `язык`, `обучение`, `отношения`.

`метатеги` описывают сам артефакт: например, `форма:метаграмма`, `статус:авторский`, `глубина:по_выбору`. добавляй только поля, которые реально нужны поиску, передаче или проверке. не кодируй в тегах диагнозы, скрытый профиль или неподтверждённую готовность человека.

авторская форма не становится машинной командой, доказательством, обещанием результата или правом воздействовать на человека. рядом всегда остаются обычное прочтение, статус, контекст и ссылка на источник, если он есть. неизвестное значение обозначай как `неизвестно`.

пример пустого манифеста интеграционной формы ::

```yaml
форма: скриптоцереяна
имя: ""
фраза_или_знак: ""
простое_прочтение: ""
цель: ""
связи:
  - ветвь: ""
    относится_к: ""
    основание: ""
граница_применения: ""
статус: авторская
источник_или_влияние: неизвестно
теги: []
метатеги:
  форма: скриптоцереяна
  приватность: выбрать
исполнение: отсутствует
```

заполняй только нужные поля. пустые поля можно удалить; не вписывай приватные сведения в публичную версию.

смысл лучше хранить в ясной формулировке, а не в россыпи символов. если краткость мешает, вернись к полному тексту.
